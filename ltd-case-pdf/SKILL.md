# 枢纽云客户案例 PDF

用户提供文章与本次客户的 Logo 即可开始。客户 Logo 可提供 PNG、JPEG、WebP、SVG 等常见格式，不要求用户先转换或抠图。Logo 输入字段 logo 仅用于封面右侧的客户标识。左侧枢纽云 Logo 自动读取技能自带的 assets/ltd-logo.png，无需用户重复上传。固定来源为 https://uploadfile.ltdcdn.com/uploadfilev2/image/0/16/222/2024-03/17115094638935.png 。仅在内置文件缺失、损坏或用户要求刷新时，从该地址恢复并确认 PNG 可读取。修改已有案例时可沿用已有文章，仅更新客户 Logo。根据文章识别客户简称、所属行业、案例主题、章节与配图。用户指定的文案优先。缺少封面文案时，从原文提炼一到两行主标题和一句副标题，保持事实可追溯。行业名称使用简洁的行业名，例如“检测认证”，不重复“行业”二字。

## 客户 Logo 预处理

保留用户提供的原件，另存封面用透明 PNG。若原件已有透明底，直接使用；若是 SVG，按原矢量内容转换为透明 PNG；若是照片或带底色的位图，先做背景移除。抠图只改变背景，保持图形、字母、中文、注册标记、颜色和间距准确，不重绘品牌。完成后检查 alpha 通道，并把透明图放到封面渐变上预览。封面按 Logo 实际可见图形范围等比缩放，不按透明画布尺寸决定大小。左侧枢纽云 Logo 保持定稿尺寸；右侧客户 Logo 的可见图形最大宽 112 pt、高 76 pt，不压过左侧标识，并保留初版封面的右边距约 130 pt（右缘位于 PDF 页面 x=465 pt）。若细线、字样或标记在抠图中受损，应重新处理；不能可靠保真时，保留原图并用协调的浅色底承载，不交付失真的 Logo。JSON 的 logo 指向最终验收通过的文件。

## 从原稿准备排版数据

在当前项目的临时目录制作 UTF-8 JSON，作为排版中间文件，由 Codex 完成，不要求用户填写。按原顺序读入粘贴文本、Markdown、HTML，或从提供的文档提取正文、图表与图注。保留文字、数据、链接、案例信息和原有资料说明；将网页章节序号等装饰结构转为版式元素。仅在原稿没有标题时补中性小标题。原文引用的图片应取原图，在本地保存，保留纵横比；若图片无法取得，说明具体缺失哪张。客户 Logo 使用清晰原文件，SVG 等必要时先转透明 PNG。

示例展示字段，实际内容逐案填写：

~~~json
{
  "client": "客户简称",
  "industry": "客户所属行业",
  "logo": "assets/customer.png",
  "title": ["主标题第一行", "主标题第二行"],
  "subtitle": "由本文内容提炼的副标题",
  "sections": [
    {"heading": "案例背景", "blocks": [
      {"type": "lead", "text": "引言原文"},
      {"type": "p", "html": "保留<strong>强调</strong>与原文链接。"},
      {"type": "figure", "path": "assets/figure-01.png", "caption": "原图注"}
    ]}
  ]
}
~~~

正文块类型有 p、lead、h3、figure、table。文字用 text（纯文本）或 html（行内强调、换行与超链接）。表格使用 rows 二维字符串数组，可加 header: true 让首行在续页重复。目录取 sections 的 heading，包括实际存在的案例信息或资料说明。路径相对于 JSON 文件；每个案例使用独立临时目录。

## 固定搭配与配色

- 封面保留浅色渐变底、左侧枢纽云 Logo、右侧客户 Logo 与中间连接线。依次安排“枢纽云 ✖ 客户简称”、案例标题、短横线、副标题、“营销枢纽好，用好客来找”。底栏为“枢纽云·〔行业〕行业客户案例”和“LTD.COM/CASE”。使用可选择、可放大的 PDF 文字。
- 目录保留“目录 / CONTENTS”、浅色交替条目、序号和实际起始页。正文页眉为“枢纽云 / 客户成功案例”；页脚为“枢纽云·〔行业〕行业案例”，右侧为全册页码。
- 末尾使用内置 assets/about.pdf 的全部 7 页，保留原有文案、标识、图片和二维码，更新可见页码。页数、章节数和目录项数按新稿计算。
- 默认沿用定稿。若给了颜色，在 JSON 增加 palette 对象，用 #RRGGBB 设置颜色。primary 为主蓝（#0F88F1），deep 为深色标题（#075EAB），yellow 为第一强调色（#F4CA33），green 为第二强调色（#AECB45），light 为渐变亮色（#66B1F2），pale 为浅底（#ECE7FA），lavender 为底栏色（#BAB8D9）。只给一种颜色时，由它推导深色标题、柔和渐变和浅色底，协调各角色；给色卡时按亮度和用途分配。Logo 与固定附录保留原色。

## 生成与验收

调用本技能目录内的 scripts/generate.py，以 JSON 路径和目标 PDF 路径为两个参数。优先使用工作区依赖运行时的 Python，需要 reportlab、pypdf、Pillow、lxml，自定义渐变另需 numpy。技能随附 Noto Sans SC 常规体、粗体及 DejaVu Sans 符号字体，统一用于正文、封面、目录、页码和固定附录的排版文字。字体许可保存在 assets/fonts 并附入成品 PDF。替换配图时，图内已有字样与品牌标识的授权需由素材来源确认。

在项目输出目录生成“客户简称_枢纽云客户成功案例.pdf”。渲染检查封面、客户 Logo 的透明边缘与清晰度、目录、每一页正文的分页和附录衔接，核对原文、配图数量、目录起始页、行业页脚和末页页码。发现独立残段或大块空白时，先检查是否由图片尺寸、图注或段落整体移到下页造成；优先调整分页或图片尺寸，同时保持配图可读与原文顺序。若空白仍明显，可在空白区加入与整册视觉一致的重点句、要点卡或简洁流程图，内容仅从本文已有信息提炼，不添加新事实或数据，也不遮挡正文、页眉和页脚。新增元素须标明是案例要点或摘要，避免被误认为原稿中的新段落；重新渲染相关页面，并核对页数和目录。最终交付 PDF 链接。
