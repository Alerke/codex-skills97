# 多语言配置与运行时

本规范定义 LTD 多语言配置、模板替换和列表运行时读取方式。配置根 key 使用 `i18n`，平台控件类型固定为 `input_type: "i18n"`；产品列表与商品列表使用同一套语言逻辑。

## 1. 数据结构

外层 key 是语言代码，内层 key 是固定翻译键名。新配置默认完整保留 `zh-cn`、`zh`、`en`、`kr`、`ru`、`jp` 六种标准语言，内层 key 集合保持一致；维护现有模块时尊重项目实际语言范围。

```js
const i18n = $[i18n];
```

- 可导入配置 JSON 中，`i18n.value` 和 `i18n.default_value` 是可再次 `JSON.parse` 的字符串化 JSON。
- 可导入配置项必须同时包含 `"key": "i18n"` 与 `"input_type": "i18n"`。二者字符串相同，但前者是占位符根 key，后者是平台多语言控件类型。
- 模板完成变量替换后，标准 `$[i18n]` 输出为可直接交给 JavaScript 使用的对象；不要默认执行 `JSON.parse($[i18n])`。
- 只有维护旧项目且实际观察到运行时输出字符串时，才在集中归一化函数中兼容一次字符串解析。
- 未替换的 `$[i18n]`、数组、`null` 或非对象值视为无效配置，回退模块内置中文文案。
- 平台输出时会自动移除 `_comments`，运行时代码不得依赖该字段。

## 2. 语言选择优先级

按以下顺序确定原始语言：

1. URL 查询参数 `editor_language_type`。
2. `localStorage.getItem('lang')`。
3. 默认语言 `zh-cn`。

标准映射：

```js
const langMap = {
  'zh-cn': 'zh-cn',
  zh: 'zh',
  'zh-tw': 'zh',
  'zh-hk': 'zh',
  en: 'en',
  ko: 'kr',
  kr: 'kr',
  ru: 'ru',
  ja: 'jp',
  jp: 'jp'
};
```

- 原始语言先转为字符串、去除首尾空白并转为小写，再执行映射。
- 不在映射表中的值回退 `zh-cn`。
- `URLSearchParams` 在目标 WebView 不稳定时先特性检测；不可用时用当前模块内的安全查询参数读取函数，不引入整套 polyfill。
- 读取 `localStorage` 使用 `try/catch`，避免隐私模式或宿主限制导致模块初始化中断。

## 3. 文案回退

按键读取时依次尝试：

1. `i18n[lang][key]`。
2. `i18n['zh-cn'][key]`。
3. 模块内置中文默认值。

不要只在整种语言缺失时回退；当前语言对象存在但某个键缺失时，也必须进行逐键回退。空字符串可能是用户主动隐藏文案的配置，默认只把 `undefined` 和 `null` 视为缺失。

```js
const t = (key) => {
  const current = i18n[lang] || {};
  const fallback = i18n['zh-cn'] || {};
  if (current[key] !== undefined && current[key] !== null) return String(current[key]);
  if (fallback[key] !== undefined && fallback[key] !== null) return String(fallback[key]);
  return defaultTexts[key] || '';
};
```

包含 `{count}`、`{current}`、`{total}` 等变量的文案只对已知占位符做字符串替换，不把翻译值作为可执行模板或 HTML。

## 4. 多实例与安全渲染

- 语言只需在实例初始化时计算一次；若任务要求编辑器内实时切换语言，再监听平台明确提供的语言事件。
- DOM 查询限制在当前产品/商品列表根节点，不使用 `document.querySelector('.title')` 修改其他实例。
- 普通文案使用 `textContent`。需要属性值时用 `setAttribute`；除非经过明确的富文本净化流程，不把翻译内容写入 `innerHTML`。
- 请求参数 `language_type` 和界面文案使用同一个归一化后的 `lang`，避免接口语言与 UI 语言不一致。

```js
const title = root.querySelector('.pl-title');
if (title) title.textContent = t('title');
```

## 5. 推荐列表键名

仅保留模块实际使用的键。常见列表文案包括：

`product_title`、`goods_title`、`subtitle`、`search_placeholder`、`search`、`clear`、`all`、`default_sort`、`newest`、`price_asc`、`price_desc`、`loading`、`empty`、`reset`、`error`、`retry`、`previous`、`next`。

六种语言必须拥有一致的键；不要为了复用旧配置同时保留多个语义相同的键。

### 类型标题

默认可见标题不能使用固定 `title`。先解析有效 `moduleType`，再读取对应键：

```js
const titleKeyMap = {
  product: 'product_title',
  goods: 'goods_title'
};
const defaultTypeTitles = {
  product: '产品列表',
  goods: '商品列表'
};

const applyModuleTypeText = (moduleType) => {
  const titleKey = titleKeyMap[moduleType];
  const titleText = titleKey ? t(titleKey) : '';
  const accessibleTitle = titleText || defaultTypeTitles[moduleType] || '';
  const title = root.querySelector('.pl-title');
  if (title) title.textContent = titleText;
  if (accessibleTitle) root.setAttribute('aria-label', accessibleTitle);
};
```

- 新配置的六种语言均保留 `product_title/goods_title`，语言对象缺少时按逐键规则回退。
- 模块现有的 `defaultTexts` 也必须包含 `product_title: "产品列表"` 与 `goods_title: "商品列表"`，保证可见标题在 i18n 缺失时仍正确。
- HTML 初始结构不硬编码“产品列表”或“商品列表”；解析类型后、展示模块前立即写入，避免 goods 模块短暂显示产品标题。
- 编辑器重新替换配置或模块支持运行时类型切换时，切换适配器后必须再次调用 `applyModuleTypeText(moduleType)`。
- `.pl-title` 和根节点查询限制在当前实例内；不得更改同页其他模块标题。
- 若用户明确关闭 `show_title`，可以隐藏可见标题，但仍为根节点提供与当前类型一致的无障碍名称。

## 6. 表单运行时

当点击操作打开 LTD 表单且页面已有对应表单实例时，可直接传入同一个多语言变量：

```js
fitForm_10126.setI18n($[i18n]).setLanguage('en');
```

实例名和语言应来自当前实际表单与归一化语言，不能照抄示例编号或固定为 `en`。产品/商品列表只负责传递配置，不复制表单自身的多语言运行时。

## 7. 验收

- 六种标准语言和翻译键集合完整一致。
- 编辑器 URL 参数优先于本地语言，繁中/韩文/日文别名映射正确。
- 当前语言缺失与单个键缺失都能逐级回退。
- 配置导入字符串与运行时对象没有被混淆或重复解析。
- 多语言配置项的 key 为 `i18n`，`input_type` 也严格等于 `i18n`。
- `_comments` 不参与运行时逻辑，翻译内容没有造成跨实例污染或 HTML 注入。
- UI 文案和接口 `language_type` 使用同一语言值。
- `product_title/goods_title` 在每种语言中存在；切换 moduleType 后当前实例的可见标题与 `aria-label` 同步更新。
