# 枢纽云客户案例框架

## 一、固定逻辑与可变内容

批量客户案例采用约 70% 固定逻辑、30% 客户化表达：

- 固定：证据边界、叙事顺序、场景分析方法、枢纽云关联方式、参考资料结构。
- 可变：标题、行业痛点、客户角色、核心功能、业务闭环、章节名称和可借鉴对象。

不要要求每篇文章使用完全相同的小标题或相同数量的功能章节。

## 二、标准文章结构

### 1. 结果型标题

优先使用以下组合之一：

- 业务门槛或特色 + 经营结果：客户如何用营销枢纽完成某条业务路径
- 行业痛点 + 解决方式：客户如何把某项业务搬到官网
- 功能差异 + 客户价值：从某个动作到某个结果的业务闭环

标题中的结果必须是可验证的能力变化，不得把预期价值写成已经实现的业绩。

### 2. 客户信息卡

至少包含：客户名称、官网、行业和合作时间。缺失字段不补造。

### 3. 场景化导语

从目标客户熟悉的业务难题切入，通常用一个具体动作或判断说明原有流程为何费时、分散或难以持续。导语结尾引出客户建设业务型官网的目标。

### 4. 客户是谁

回答四个问题：

- 提供什么产品或服务；
- 服务哪些群体；
- 通过什么方式获客和成交；
- 线上与线下如何交付。

### 5. 为什么建设业务型官网

说明企业希望解决的核心经营问题，例如找产品难、报价重复、询盘分散、交易规则复杂、服务衔接困难或客户无法沉淀。

### 6. 核心功能场景

选择 2—4 个最关键场景，每个场景使用四段式逻辑：

1. **业务问题**：哪个角色在什么环节遇到什么困难；
2. **官网动作**：客户进入网站后可以完成什么；
3. **枢纽云能力**：哪个可确认的功能承接该动作；
4. **经营价值**：该功能如何减少摩擦、连接流程或沉淀关系。

不要只写“网站具有某功能”，也不要只写“枢纽云可以做什么”。

### 7. 业务闭环

根据行业给出一条真实路径：

- 电商：发现商品 → 筛选 → 下单 → 履约 → 会员复购；
- B2B：了解企业 → 查看产品 → 提交询盘 → 销售跟进 → 成交交付；
- 服务：了解服务 → 预约咨询 → 方案沟通 → 服务交付 → 持续运营；
- 招商：了解品牌 → 查看政策 → 提交申请 → 区域跟进 → 加盟服务；
- 外贸：多语言浏览 → 产品筛选 → 海外询盘 → 商务跟进 → 出口交付。

只有资料明确时才写实际路径；否则标为建议性分析。

### 8. 与营销枢纽的关系

围绕与客户实际相关的“营、销、管、服”解释：

- 营：官网内容、搜索入口、产品与案例帮助客户发现企业；
- 销：表单、商城、询盘、预约或交易承接转化；
- 管：会员、客户身份、订单或线索形成可持续关系；
- 服：交付、售后、顾问服务与后续触达继续衔接。

不要求四项全部出现。先写客户场景，再写枢纽云能力。

### 9. 同类企业参考价值

列出 4—6 个可判断特征，让潜在客户识别自己是否适合借鉴。特征应来自业务模式，例如产品参数复杂、零批并存、价格分层、交付周期长、复购明显或需要多语言获客。

### 10. 功能亮点摘要

使用 5—8 条，每条由“功能名称 + 业务作用”组成。避免重复正文原句。

### 11. 参考资料与信息说明

分组列出客户官网资料、枢纽云产品资料和用户提供的项目事实。写明公开资料访问日期。

默认信息说明应表达：企业信息来自官网和互联网公开渠道；未调取或泄露企业内部专属后台数据；内容客观陈述可验证的网站建设与业务功能事实。若正文使用了客户经理提供的非公开项目事实，必须单独标明其来源，不能把它们归为互联网公开信息。

## 三、功能模块选择

| 客户类型 | 优先考虑的模块 |
| --- | --- |
| B2B产品企业 | 产品分类、参数筛选、搜索、询盘、线索沉淀 |
| 批发电商 | 批发目录、阶梯价格、会员折扣、在线下单 |
| 零售电商 | 商品商城、购物车、支付、订单、会员复购 |
| 服务型企业 | 服务介绍、预约咨询、表单、顾问跟进、服务交付 |
| 招商加盟 | 品牌内容、加盟政策、区域申请、招商线索管理 |
| 外贸企业 | 多语言、海外展示、产品询盘、区域客户跟进 |
| 内容营销企业 | 文章、案例、资料下载、搜索获客、线索转化 |
| 会员经营企业 | 注册登录、等级权益、分层触达、续购复购 |
| 定制业务企业 | 需求提交、方案沟通、报价、订单、项目交付 |

只有在目标网站或项目资料能够确认时，才把模块写成已经启用的功能。

## 四、批量输入清单

每个客户尽量收集：

1. 企业名称、官网、行业、合作时间；
2. 核心产品或服务；
3. 主要客户群体；
4. 原有获客、成交和交付方式；
5. 建设官网前的主要问题；
6. 官网当前可见功能；
7. 项目定制功能及配置规则；
8. 线上与线下如何衔接；
9. 客户经理对项目目标的概括；
10. 可公开使用的图片与说明；
11. 对应的枢纽云产品名称和链接；
12. 有证据支持的成果、反馈或经营变化。

## 五、成稿审查

- 客户身份、业务、功能和链接是否可追溯；
- 项目事实与公开事实是否正确区分；
- 是否出现未经证实的后台数据或经营成果；
- 每个功能是否连接了具体业务场景与价值；
- 枢纽云关联是否自然且只涉及可确认能力；
- 是否清楚说明网站的实际用途和业务闭环；
- 同行业读者能否判断案例是否与自己有关；
- 批量文章是否真正体现行业与客户差异。
