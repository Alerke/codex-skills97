# 官网文章编辑排版

把原始文章转换为可直接粘贴到官网富文本编辑器的 HTML 正文片段。默认只处理正文，不复制网站标题栏、作者信息、二维码、浮窗、底部工具栏、推荐文章或“阅读全文”等平台外壳。

## 工作方式

1. 识别内容角色：导语、普通段落、关键短语、章节、图片与图注、列表、强调结论、行动按钮和来源参考。
2. 保留事实、专有名词、数字、链接与段落逻辑。排版可以重组视觉层级，不擅自改写结论或补造信息。
3. 默认输出富文本正文片段；只有用户明确要求完整网页时，才增加文档外壳、页面标题和元信息。
4. 正文存在两个及以上并列章节时，使用 `01`、`02`……编号；不要为了视觉效果硬凑固定章节数。
5. 生成前读取 [references/layout-spec.md](references/layout-spec.md) 和 [references/color-palettes.md](references/color-palettes.md)。需要精确颜色值时读取 [references/color-palettes.json](references/color-palettes.json)，快速起稿可使用 [assets/article-fragment-template.html](assets/article-fragment-template.html)。
6. 输出后运行 `scripts/validate_fragment.py <html-file>`；完整网页模式追加 `--allow-h1`。

## 配色选择

- 用户指定配色名称或 ID 时直接使用，不再询问。
- 用户提供品牌色时，从八套配色中选择最接近的一套；只有用户明确要求时才基于品牌色扩展新方案。
- 用户没有指定时，运行 `scripts/select_palette.py --title "文章标题"` 自动选择。批量排版或同一任务已有成稿时，使用一个或多个 `--avoid` 排除最近采用的方案，避免连续文章配色相同。
- 同一篇文章只使用一套配色。颜色只改变视觉令牌，不改变字号、间距、组件结构或内容顺序。
- 交付和发布记录必须写明采用的配色名称与 ID，方便后续复现。

## 内容与样式约束

- 正文字号 17px、行高 1.9、两端对齐；中文字体栈优先 `PingFang SC` 与 `Microsoft YaHei`。
- 色彩从所选方案的语义令牌读取：正文、次级正文、标题、强调、章节编号、链接、分隔线、按钮和柔和背景。不得跨方案拼色。
- 章节标题使用 `font-size:24px;font-size:clamp(24px,3.6vw,40px)` 及 1.3 行高；第一条声明是旧环境回退。
- 默认识别关键段落中的核心概念、关键时间或数据、结果与业务价值，并把其中最值得扫读的短语用 `<strong>` 标注。概念、结果和价值使用当前配色的 `emphasis`，时间、版本或数据节点可使用 `accent`；统一使用 700 字重。一般每个关键段落突出 1—2 个短语，普通过渡段可不标注，不整段变色，不在参考文献区默认添加强调。详细规则见 [references/layout-spec.md](references/layout-spec.md) 的“关键短语强调”。
- 每张正文图片都默认与自动生成的图注组成一个完整图片组，无需用户逐张提供图注。图片使用块级、100% 宽度、自动高度，并写有意义的 `alt`；图注紧跟图片，按出现顺序使用“图 1｜说明”“图 2｜说明”连续编号。详细样式与内容规则见 [references/layout-spec.md](references/layout-spec.md) 的“图片与图注”。
- 图注只描述图片在文章中的作用，不编造来源或截图性质。真实后台截图、模拟对话示意图、外部来源图片等身份只有在输入可确认时才写入图注；信息不足且影响准确性时列为待确认项。
- 不得猜测图片地址；缺图时在审阅说明中列出“待补图片”，不要输出失效的 `src`。
- 普通段落以 18px 上间距形成节奏；章节上下留白 42px；大图与文字区块齐边，不加装饰阴影。
- 重要结论可使用上下细边线或左侧强调线，避免大面积色块、渐变、表情符号和过度圆角。
- CTA 默认两个并排按钮：一个深色实心、一个白底描边。按钮文案和目标地址必须来自输入或用户确认。
- 参考文献默认使用“编号固定列＋正文自适应列”的两列结构：编号独占 48px，正文占据剩余宽度；续行必须与编号后的首行文字左边缘对齐。不得用负 `text-indent` 或首行缩进模拟悬挂缩进。正文保持两端对齐、末行左对齐；短域名整体换行但不得拆成单个字符。来源保留可读标题与真实 URL，不显示冗长裸链接，不得伪造引用。详细规则见 [references/layout-spec.md](references/layout-spec.md) 的“来源参考”。

## 富文本兼容性

- 关键样式写在元素 `style` 属性中，不依赖外部 CSS、脚本、CSS 变量或构建工具。
- 不输出 `script`、`iframe`、`form`、事件处理属性或跟踪代码。
- 新窗口链接使用 `target="_blank" rel="noopener noreferrer"`。
- 正文片段不重复 `<h1>`；官网后台通常负责文章标题。图片组优先使用 `figure`、`img`、`figcaption`；其他内容优先使用 `section`、`p`、`h2`、`ul`、`li`、`a` 等常见标签。
- 不使用固定内容宽度包裹正文片段；宽度由官网详情页模板控制。完整网页模式才使用约 680px 的阅读宽度。
- 最终 HTML 不得残留 `{{PLACEHOLDER}}`、本地路径、Base64 图片或无法公开访问的资源地址。

## 交付格式

1. **排版说明**：内容结构、配色名称与 ID、字号、关键短语强调、图片、图注和 CTA 规则。
2. **HTML**：可粘贴的正文片段或用户要求的完整网页。
3. **待确认项**：只列缺失的图片、链接、署名或平台限制；没有则写“无”。

信息不足且会影响事实、链接或图片时先询问；仅影响轻微视觉细节时可采用本技能规则自动选择，并明确说明该选择。
